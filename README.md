# cs-405
Adopting a secure coding standard helps ensure all developers on a team are on the same page in regards to expectations regarding how to approach creating a protected system. This includes concepts such as being careful with data types and how they're used, means of processing input, as well as utilizing a coding language's capabilities to ensure complete developer control over logic flow. It is always important that these ideas be ever present in the mind of developers; especially in the beginning as it reduces a lot of redundant work and mitigates a lot of risks that would otherwise exist otherwise. It takes away lot of the cost of time in guesswork for developers when/if an issue does arise because there are fewer avenues to exploit in the product. Having a concept of zero trust in the system is also an important way to protect against these threats. If every user or input is treated as if it is malicious, then that creates an environment where accidentally granting access to more resources than a user should are hopefully entirely eliminated through regular means. Of course, additional protections could be enacted through the creation and enforcement of security policies both virtual and physical that would prevent attacks from means that might exist outside of the system. This could be concepts such as housing physical resources inside locked rooms, having physical barriers around work stations of developers, as well as having password-controlled access to developer environments to name a few.
